# 구현 이력

> 각 Phase의 구현 내용, 생성된 파일, 설계 결정 사항을 기록한다.

---

## Phase 1. 프로젝트 기반 및 인증

### 생성된 파일
- `soma-backend/src/index.js` — Express 서버, CORS, 라우터 등록
- `soma-backend/src/config/db.js` — MySQL2 커넥션 풀
- `soma-backend/src/middleware/auth.js` — JWT 인증 미들웨어 (`authenticate`, `optionalAuth`)
- `soma-backend/src/controllers/authController.js` — 회원가입, 로그인, 내 정보 조회
- `soma-backend/src/routes/auth.js` — `/api/auth` 라우터
- `soma-frontend/src/hooks/useAuth.ts` — 로그인/회원가입/로그아웃 훅, 토큰 복원
- `soma-frontend/src/api/index.ts` — fetch 기반 API 클라이언트
- `soma-frontend/src/pages/Auth.tsx` — 로그인/회원가입 페이지

### 설계 결정
- JWT 토큰을 `localStorage`에 저장하고 모든 API 요청 헤더에 `Authorization: Bearer` 포함
- 앱 시작 시 `authApi.me()`로 토큰 유효성 검증 후 user 상태 복원
- 비밀번호는 `bcrypt` salt 12로 해싱

## Phase 2. 강의 목록 및 상세

### 생성된 파일
- `soma-backend/src/controllers/courseController.js` — 강의 목록, 상세 조회
- `soma-backend/src/routes/courses.js` — `/api/courses` 라우터
- `soma-frontend/src/pages/CourseList.tsx` — 강의 목록 페이지 (탭 필터, 검색)
- `soma-frontend/src/pages/CourseDetail.tsx` — 강의 상세 페이지
- `soma-frontend/src/types/index.ts` — Course, Lecture, Review, QnaQuestion 등 타입 정의

### 설계 결정
- `lecture_count`, `total_hours`는 courses 테이블에 저장하지 않고 lectures 테이블에서 `COUNT(DISTINCT l.id)`, `SUM(l.duration_sec)/3600`으로 실시간 계산
- 강의 상세 조회 시 `optionalAuth` 미들웨어로 로그인 여부에 따라 `isEnrolled`, `isWishlisted` 포함
- 커리큘럼은 주차별로 그룹핑하여 `{ 1: [...], 2: [...] }` 형태로 반환

## Phase 3. 수강 신청 및 내 수업

### 생성된 파일
- `soma-backend/src/controllers/enrollmentController.js` — 수강 신청, 내 수강 목록, 찜 토글, 수강 취소
- `soma-backend/src/routes/enrollments.js` — `/api/enrollments` 라우터
- `soma-frontend/src/pages/MyPage.tsx` — 내 수업 페이지 (진도율 바, 이어서 듣기)

### 설계 결정
- 수강 취소 시 해당 강의의 progress 데이터도 함께 삭제 (서브쿼리로 lecture_id 목록 조회)
- 진도율은 `completed_lectures / lecture_count * 100`으로 백엔드에서 계산하여 반환
- 찜하기는 토글 방식 — 이미 찜한 경우 DELETE, 아닌 경우 INSERT

## Phase 4. 강의 플레이어

### 생성된 파일
- `soma-backend/src/controllers/progressController.js` — 진도 저장(upsert), 내 진도 조회
- `soma-backend/src/routes/progress.js` — `/api/progress` 라우터
- `soma-frontend/src/pages/Player.tsx` — 강의 플레이어 페이지

### 설계 결정
- YouTube iframe API `enablejsapi=1` + `infoDelivery` 이벤트로 실시간 재생 시간 수신
- 재생 시간을 `localStorage`와 DB 양쪽에 동시 저장 (fire-and-forget)
- 강의 전환, 페이지 이탈, 브라우저 종료(`beforeunload`) 시 저장
- 강의 변경 시 iframe `key` prop 변경으로 강제 리마운트 → 영상 교체 보장
- 각 강의의 `video_url`(유튜브 ID)은 DB에서 받아서 사용

## Phase 5. 후기 및 Q&A

### 생성된 파일
- `soma-backend/src/controllers/reviewController.js` — 후기 작성, 목록 조회, 삭제
- `soma-backend/src/routes/reviews.js` — `/api/courses/:courseId/reviews` 라우터
- `soma-backend/src/controllers/qnaController.js` — 질문 등록, 답변 등록, 목록 조회
- `soma-backend/src/routes/qna.js` — `/api/courses/:courseId/qna` 라우터

### 설계 결정
- 후기는 수강 중인 강의에만 작성 가능 (enrollments 테이블 확인)
- 후기는 강의당 1개만 작성 가능 (UNIQUE KEY 확인)
- Q&A 답변자의 role이 instructor이면 "강사" 뱃지 표시
- Q&A는 아코디언 UI로 펼치기/접기

## Phase 7. 역할 기반 접근 제어

### 수정된 파일
- `soma-backend/src/controllers/authController.js` — role 파라미터 추가, 강사 가입 시 instructors 자동 등록
- `soma-backend/schema.sql` — role ENUM에 instructor 추가
- `soma-frontend/src/pages/Auth.tsx` — 학생/강사 역할 선택 카드 UI 추가
- `soma-frontend/src/components/Nav.tsx` — role별 메뉴 분기

### 설계 결정
- 회원가입 시 role을 선택하면 백엔드에서 검증 후 저장 (user / instructor만 허용, admin은 직접 DB 설정)
- 강사 가입 시 instructors 테이블에 자동 등록 (name 동일하게)
- JWT 토큰에 role 포함 → 프론트에서 역할별 UI 분기

## Phase 8. 강사 대시보드

### 생성된 파일
- `soma-backend/src/controllers/instructorCourseController.js` — 강의 CRUD, 커리큘럼 CRUD, 공개/비공개 토글
- `soma-backend/src/routes/instructorCourses.js` — `/api/instructor/courses` 라우터
- `soma-backend/src/routes/upload.js` — `/api/upload/thumbnail` 파일 업로드 라우터
- `soma-frontend/src/pages/InstructorDashboard.tsx` — 강사 대시보드 페이지

### 설계 결정
- instructor_id는 `users.name`으로 instructors 테이블에서 조회 (`getInstructorId` 헬퍼)
- 강의 추가 시 `sort_order`는 `MAX(sort_order) + 1`로 자동 계산
- 썸네일은 multer로 서버에 저장 (`/uploads` 폴더), 정적 파일 서빙
- 유튜브 링크 자동 파싱: `youtu.be/ID`, `youtube.com/watch?v=ID`, ID 직접 입력 모두 지원
- 강의 등록 후 공개 버튼을 눌러야 학생에게 노출 (`is_published = 0` 기본값)
