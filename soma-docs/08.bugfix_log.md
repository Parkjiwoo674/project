## BUG-001: 강의 전환 시 영상이 바뀌지 않는 문제

### 발생일
2026-04-06

### 증상
Player 페이지에서 사이드바의 다른 강의를 클릭해도 유튜브 영상이 바뀌지 않고 첫 번째 영상이 계속 재생된다.

### 원인
React에서 `<iframe src={newUrl} />`처럼 src만 변경하면 브라우저가 기존 iframe을 재사용하고 새 URL을 로드하지 않는 경우가 있다. YouTube iframe은 특히 이 문제가 두드러진다.

### 수정 내용

**파일: `soma-frontend/src/pages/Player.tsx`**
```tsx
// 변경 전 — src만 변경
<iframe src={`https://www.youtube.com/embed/${videoId}?...`} />

// 변경 후 — key prop으로 강제 리마운트
const [videoKey, setVideoKey] = useState(0);

const selectLec = (lec: Lecture) => {
  setVideoKey((k) => k + 1); // key 변경 → iframe 완전히 새로 생성
  ...
};

<iframe key={videoKey} src={`https://www.youtube.com/embed/${videoId}?...`} />
```

### 검증
- 사이드바에서 강의 클릭 시 영상이 즉시 교체되는 것 확인

## BUG-002: 영상 ID 매핑 오류로 항상 첫 번째 영상만 재생되는 문제

### 발생일
2026-04-06

### 증상
강의 2번, 3번을 클릭해도 항상 첫 번째 영상(0Ad4j-qlG04)이 재생된다.

### 원인
`VIDEOS_BY_ORDER`를 강의 DB id로 매핑했는데, 실제 DB의 lecture id는 1, 2, 3, 4...가 아닌 다른 값일 수 있다. 예를 들어 lecture id가 10, 20, 30이면 매핑 테이블에 해당 키가 없어 항상 `DEFAULT_VIDEO`로 fallback된다.

### 수정 내용

**파일: `soma-frontend/src/pages/Player.tsx`**
```tsx
// 변경 전 — lecture id로 매핑 (오류)
const VIDEOS_BY_ORDER: Record<number, string> = { 1: "...", 2: "...", ... };
function getVideoId(allLectures, lecId) {
  const idx = allLectures.findIndex((l) => l.id === lecId);
  return VIDEOS_BY_ORDER[idx + 1] ?? DEFAULT_VIDEO;
}

// 변경 후 — DB의 video_url 직접 사용
function getVideoId(lec: Lecture): string {
  if (lec.video_url) return lec.video_url;
  return DEFAULT_VIDEO;
}
```

### 검증
- 각 강의의 video_url이 DB에 저장된 값으로 재생되는 것 확인

## BUG-003: 새로고침 시 로그인 상태가 풀리는 문제

### 발생일
2026-04-02

### 증상
로그인 후 페이지를 새로고침하면 로그인이 풀리고 비로그인 상태로 표시된다.

### 원인
`useAuth` 훅에 토큰 복원 로직이 없었다. localStorage에 토큰이 있어도 앱 시작 시 user 상태가 null로 초기화된다.

### 수정 내용

**파일: `soma-frontend/src/hooks/useAuth.ts`**
```ts
// 추가 — 앱 시작 시 토큰으로 유저 복원
useState(() => {
  const token = localStorage.getItem("soma_token");
  if (!token) return;
  authApi.me().then((res) => {
    if (res.data) setUser(res.data);
  }).catch(() => localStorage.removeItem("soma_token"));
});
```

### 검증
- 로그인 후 새로고침해도 로그인 상태 유지 확인

## BUG-004: goTo 타입 에러 — 인수 개수 불일치

### 발생일
2026-04-08

### 증상
`CourseList`, `CourseDetail`에서 `goTo("detail", c.id)` 호출 시 TypeScript 에러 발생.
```
Error: Expected 1 arguments, but got 2.
```

### 원인
각 페이지 컴포넌트의 `goTo` 타입이 `(page: PageKey) => void`로 선언되어 있어 두 번째 인수(id)를 받지 못한다.

### 수정 내용

**파일: `soma-frontend/src/pages/CourseList.tsx`, `CourseDetail.tsx`, `Landing.tsx`**
```ts
// 변경 전
interface CourseListProps {
  goTo: (page: PageKey) => void;
}

// 변경 후
interface CourseListProps {
  goTo: (page: PageKey, id?: number) => void;
}
```

### 검증
- TypeScript 에러 0건 확인

## BUG-005: previewLeft state 미사용 경고

### 발생일
2026-04-06

### 증상
미리보기 타이머 카운트다운 표시를 제거한 후 `previewLeft` state가 선언만 되고 읽히지 않아 TypeScript 경고 발생.

### 원인
`useState`로 선언한 `previewLeft`를 JSX에서 사용하지 않게 되었으나 타이머 로직에서 여전히 `setPreviewLeft`를 호출하고 있었다.

### 수정 내용

**파일: `soma-frontend/src/pages/CourseDetail.tsx`**
```ts
// 변경 전 — state로 관리 (미사용 경고)
const [previewLeft, setPreviewLeft] = useState(30);

// 변경 후 — ref로 변경 (렌더링 불필요)
const previewLeft = useRef(30);
// setPreviewLeft(30) → previewLeft.current = 30
// setPreviewLeft((s) => s - 1) → previewLeft.current -= 1
```

### 검증
- TypeScript 경고 0건 확인

## BUG-006: git push rejected — remote에 로컬에 없는 커밋 존재

### 발생일
2026-04-08

### 증상
```
! [rejected] main -> main (fetch first)
error: failed to push some refs to 'https://github.com/...'
```

### 원인
GitHub에 다른 기기 또는 웹에서 직접 커밋한 내용이 있어 로컬 브랜치가 원격보다 뒤처진 상태.

### 수정 내용
```bash
git pull origin main --rebase
git push origin main
```
`--rebase` 옵션으로 원격 커밋을 로컬 커밋 아래에 적용한 뒤 push.

### 검증
- `main -> main` 정상 push 확인
