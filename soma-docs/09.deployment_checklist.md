# 🚀 SOMA 배포 전 체크리스트

## ❌ 치명적 문제 (반드시 수정 필요)

### 1. **민감한 정보가 .env 파일에 노출됨**
현재 `.env` 파일이 Git에 커밋되어 있습니다!

**해결 방법:**
```bash
# 백엔드
cd soma-backend
git rm --cached .env
echo ".env" >> .gitignore

# 프론트엔드
cd soma-frontend
git rm --cached .env
echo ".env" >> .gitignore

git commit -m "Remove .env files from git"
```

**대신 `.env.example` 파일 생성:**
```bash
# soma-backend/.env.example
PORT=4000
DB_HOST=localhost
DB_PORT=3306
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_NAME=soma_db
JWT_SECRET=your_jwt_secret_here_change_this
JWT_EXPIRES_IN=7d
TOSS_SECRET_KEY=your_toss_secret_key
CLIENT_URL=http://localhost:5173
ADMIN_SECRET_CODE=your_admin_code
```

### 2. **프로덕션 환경 변수 설정 필요**

**soma-backend/.env (프로덕션용)**
```env
PORT=4000
DB_HOST=your_production_db_host
DB_USER=your_production_db_user
DB_PASSWORD=strong_password_here
DB_NAME=soma_db
JWT_SECRET=very_long_random_string_at_least_32_chars
JWT_EXPIRES_IN=7d
TOSS_SECRET_KEY=live_sk_xxxxx  # 실제 Toss 라이브 키로 변경
CLIENT_URL=https://your-frontend-domain.com
ADMIN_SECRET_CODE=strong_admin_code
```

**soma-frontend/.env (프로덕션용)**
```env
VITE_API_URL=https://your-backend-domain.com/api
VITE_TOSS_CLIENT_KEY=live_ck_xxxxx  # 실제 Toss 라이브 키로 변경
```

### 3. **API URL 하드코딩 문제**

프론트엔드에서 API URL이 하드코딩되어 있을 가능성이 높습니다.

**확인 필요:**
- `soma-frontend/src/api/index.ts` 파일에서 `http://localhost:4000` 하드코딩 여부 확인
- 환경 변수 `import.meta.env.VITE_API_URL` 사용하도록 수정

### 4. **Toss Payments 테스트 키 사용 중**

현재 `.env`에 `test_gsk_docs_...` 테스트 키가 있습니다.
- 실제 결제를 받으려면 Toss Payments에서 **라이브 키** 발급 필요
- 테스트 환경에서는 실제 결제가 되지 않습니다

## ⚠️ 중요한 개선 사항

### 5. **데이터베이스 보안**

**현재 문제:**
- DB 비밀번호가 `1234`로 너무 약함
- root 계정 직접 사용

**해결 방법:**
```sql
-- 프로덕션용 DB 사용자 생성
CREATE USER 'soma_user'@'localhost' IDENTIFIED BY 'strong_password_here';
GRANT SELECT, INSERT, UPDATE, DELETE ON soma_db.* TO 'soma_user'@'localhost';
FLUSH PRIVILEGES;
```

### 6. **HTTPS 설정**

프로덕션에서는 반드시 HTTPS 사용:
- Let's Encrypt (무료 SSL 인증서)
- Cloudflare (무료 CDN + SSL)
- AWS Certificate Manager (AWS 사용 시)

### 7. **CORS 설정 강화**

```javascript
// soma-backend/src/index.js
app.use(cors({
  origin: process.env.NODE_ENV === 'production' 
    ? ['https://your-frontend-domain.com']  // 프로덕션에서는 정확한 도메인만 허용
    : ['http://localhost:5173', 'http://localhost:3000'],
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
  allowedHeaders: ['Content-Type', 'Authorization'],
}));
```

### 8. **Rate Limiting 추가**

DDoS 공격 방지:
```bash
npm install express-rate-limit
```

```javascript
// soma-backend/src/index.js
const rateLimit = require('express-rate-limit');

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15분
  max: 100, // IP당 최대 100 요청
  message: '너무 많은 요청을 보냈습니다. 잠시 후 다시 시도해주세요.'
});

app.use('/api/', limiter);
```

### 9. **로깅 시스템 개선**

프로덕션에서는 `console.log` 대신 로깅 라이브러리 사용:
```bash
npm install winston
```

### 10. **파일 업로드 보안**

현재 `/uploads` 폴더가 정적 파일로 서빙됨:
- 파일 크기 제한 확인 (현재 10MB)
- 파일 타입 검증 강화
- 프로덕션에서는 AWS S3, Cloudinary 등 사용 권장

## 🛠 권장 배포 방법

### 옵션 1: Vercel (프론트엔드) + Railway (백엔드)
- **프론트엔드**: Vercel (무료, 자동 HTTPS)
- **백엔드**: Railway (무료 티어 있음, DB 포함)
- **장점**: 설정 간단, 무료로 시작 가능

### 옵션 2: AWS
- **프론트엔드**: S3 + CloudFront
- **백엔드**: EC2 + RDS
- **장점**: 확장성 좋음, 프로덕션 레벨

### 옵션 3: 단일 서버 (VPS)
- **서버**: DigitalOcean, Linode, Vultr
- **웹서버**: Nginx (리버스 프록시)
- **프로세스 관리**: PM2
- **장점**: 완전한 제어, 비용 예측 가능
